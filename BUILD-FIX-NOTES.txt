Original failure:
  electron-builder configuration validation reported:
    configuration.linux should be a null

Remediation:
  - Removed build.linux from package.json entirely so Linux-specific metadata does not participate in validation for Windows or macOS builds.
  - Passed Linux targets explicitly in the Linux GitHub Actions step and the build:linux / build:linux:arm64 scripts: `--linux AppImage deb`.

  - Added an ES5-compatible server-rendered display route at /legacy-display/:token.
  - The generated legacy IPA is arm64-only. It does not install on 32-bit iPad 2-class hardware; use Safari on a trusted LAN or a separately maintained old Xcode/armv7 build for those devices.

Verification performed in this environment:
  - Node syntax checks for server, desktop, mobile, and legacy JavaScript: passed.
  - `npm test`: 10 tests passed.
  - Info.plist and Xcode project plist syntax validation: passed.
  - GitHub Actions workflow YAML parsing: passed.
  - Native desktop installers, Android APK, and iOS IPA were not built in this environment; GitHub Actions must produce and verify those artifacts.


V1.0.2 fix — Electron Builder auto-publishing token failure

Reported error:
  GitHub Personal Access Token is not set, neither programmatically,
  nor using env GH_TOKEN.

Interpretation:
  The Windows NSIS installer and portable EXE had already been built. The
  command then failed because electron-builder 26 can implicitly attempt a
  GitHub release publish when a tagged CI build is detected.

Remediation:
  - Added `--publish never` to every Electron Builder command in GitHub Actions.
  - Added `--publish never` to all local desktop build scripts.
  - Left release publishing to the dedicated `softprops/action-gh-release` step,
    passing GitHub's built-in `${{ github.token }}` with contents: write permission.
  - Bumped package version to 1.0.2 and added a regression test for all desktop scripts.

This removes the need for a personal access token for the desktop compilation
steps. The final release job uses the workflow's built-in GitHub token.

------------------

- Configured the static AppImage 1.0.3 toolset for Ubuntu 24.04+ to avoid the legacy FUSE2 runtime. Linux steps emit electron-builder debug output for diagnosis if they fail again.
